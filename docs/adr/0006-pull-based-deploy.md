# 0006. 배포는 CI가 밀어 넣지 않고 클러스터 안 ArgoCD가 가져간다

- 상태: 채택 (2026-10-26)

## 맥락

CI(ADR 0005)가 이미지를 만든 뒤 클러스터에 반영하는 방법은 두 가지다.

- **push 방식**: CI가 kubeconfig를 들고 `kubectl apply`·`helm upgrade`를 실행한다
- **pull 방식**: 클러스터 안의 에이전트가 Git을 보고 있다가 바뀌면 스스로 맞춘다

이 클러스터의 API(6443)는 Tailscale로만 열려 있고 공개 인바운드 포트가 없다(ADR 0004). 목표는 "Git이 유일한 변경 경로"다.

## 결정

- 클러스터 안 **ArgoCD**가 homelab repo의 `gitops/`를 주기적으로 읽어(기본 3분) 동기화한다
- 자동 동기화 + **self-heal**(누가 `kubectl`로 바꾸면 Git 상태로 되돌림) + **prune**(Git에서 지운 리소스는 클러스터에서도 삭제)
- 앱 단위는 app-of-apps. 루트 앱이 `gitops/root/`의 Application 목록을 관리한다
- 롤백은 `git revert`. ArgoCD UI의 롤백 버튼은 쓰지 않는다(자동 동기화가 곧바로 Git 상태로 되돌린다)
- ArgoCD 이후 사람은 클러스터에 조회·디버깅(get, describe, logs, port-forward)만 한다

## 검토한 대안

| 대안                                 | 장점                   | 버린 이유                                                                                        |
| ---------------------------------- | -------------------- | -------------------------------------------------------------------------------------------- |
| CI가 `kubectl apply`/`helm upgrade` | 빠름(대기 없음), 구성 단순     | 외부 CI가 클러스터 관리자 자격 증명을 가져야 함. API를 인터넷에 열거나 CI가 Tailscale에 붙어야 함. 손으로 바꾼 것이 남아도 모름           |
| Flux                               | ArgoCD보다 가벼움, CLI 중심 | 상태를 보여 주는 UI가 없음. 포트폴리오에서 "무엇이 어떤 상태인지" 보여 주기 어려움. 메모리 차이는 예산 안에서 의미 없었음(ArgoCD 실측 약 0.3GiB) |
| CI가 Tailscale에 붙어 push             | 인터넷에 API를 안 엶        | CI 비밀값에 tailnet 접근 키 + 클러스터 자격 증명이 둘 다 들어감. 새면 피해가 큼                                         |

## 결과

- **클러스터 자격 증명이 클러스터 밖으로 나가지 않는다.** CI가 털려도 할 수 있는 일은 "homelab에 PR 열기"까지다(ADR 0007이 그 PR을 검사)
- 인바운드 포트 없이 동작한다. 클러스터가 밖으로 Git을 읽으러 나갈 뿐이다
- 모든 배포가 Git 커밋으로 남는다. "지금 무엇이 떠 있나"의 답이 main이다
- **대가: 반영이 느리다.** 앱 병합부터 prod 새 파드까지 8분, 그중 절반 넘게가 폴링 대기였다(2026-11-12).
  GitHub webhook을 쓰면 줄지만 클러스터로 들어오는 경로가 필요해 7단계(Cloudflare Tunnel)에서 검토한다
- self-heal 때문에 급할 때 `kubectl edit`로 고쳐도 몇 분 안에 되돌아간다. 비상시에도 Git으로 고쳐야 한다(9단계에서 검증)

# 0001. 개인 PC 워크로드 클러스터를 범위에서 제외

- 상태: 채택 (2026-10-18)

## 맥락

기존 계획은 미니 PC를 "CI/CD·모니터링 전용"으로 두고, 실제 워크로드(커넥티드카 데모: 앱 + Kafka·MongoDB·Redis)는
개인 PC의 k3d 클러스터에서 돌리는 구조였다. 미니 PC가 Tailscale을 거쳐 개인 PC 클러스터를 ArgoCD 외부 클러스터로
등록하고, Alloy로 지표·로그를 받아 오는 방식이다.

방향을 "미니 PC = 서비스를 실제로 돌리는 GitOps 클러스터"로 바꾸면서 이 구조를 다시 검토했다.

- 개인 PC는 꺼져 있는 시간이 많다. "꺼진 것은 장애가 아님"을 구분하는 알림 설계가 따로 필요했다
- 개인 PC의 k3d API를 미니 PC에 열어야 한다(Windows Tailscale IP, 인증서 tls-san, ArgoCD 권한 범위)
- 두 클러스터를 gitops/ 안에서 구분하는 경로 설계, 클러스터별 시크릿이 필요하다

## 결정

개인 PC 클러스터를 홈랩 범위에서 뺀다. 서비스는 미니 PC k3s에 직접 배포한다.
서비스는 고정하지 않는다. 커넥티드카도 필요할 때 미니 PC 서비스로 올린다.

## 검토한 대안

| 대안 | 장점 | 버린 이유 |
|---|---|---|
| 개인 PC 클러스터 유지 (기존 계획) | 무거운 워크로드를 미니 PC 밖에서 실행 | 멀티 클러스터 설계·인증·알림 예외가 단일 노드 목표보다 커짐 |
| 나중 단계로 미룸 | 지금 작업량 감소 | 남겨 두면 문서·설계가 계속 두 갈래로 유지됨 |

## 결과

- 아키텍처가 단일 클러스터로 단순해진다. gitops 경로 구분, 외부 클러스터 등록, "꺼짐 ≠ 장애" 알림 예외가 필요 없다
- 대신 서비스가 미니 PC 16GB 안에 들어가야 한다. 기반 컴포넌트를 4GB 안팎으로 묶고([0002](0002-no-loki-memory-budget.md)),
  나머지 약 11GB를 서비스·프리뷰가 쓴다. 커넥티드카(Kafka·MongoDB)를 올릴 때 실측으로 다시 확인한다
- 멀티 클러스터 운영 경험은 포트폴리오에서 빠진다. 필요하면 EKS 실습을 별도 프로젝트로 한다

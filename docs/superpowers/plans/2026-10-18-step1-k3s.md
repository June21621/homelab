# 1단계: k3s 설치 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 미니 PC에 k3s 단일 노드를 Ansible로 설치하고, etcd 스냅샷이 S3에 올라가며 실제로 복원되는 것까지 확인한다.

**Architecture:** 관리 PC(WSL)에서 SOPS(age)로 암호화한 호스트 시크릿(k3s 토큰·백업 키)을 Ansible vars 플러그인이 복호화해 `k3s` 역할에 넘긴다. k3s는 GitHub 릴리스 바이너리를 체크섬 검증 후 설치하고 systemd 유닛·`config.yaml`로 구동한다. 호스트 포트는 Tailscale의 6443만 열고, servicelb를 끄고 Traefik은 ClusterIP로 둔다(외부 노출은 4단계 Cloudflare Tunnel).

**Tech Stack:** Ansible(ansible-core 2.21.4, community.general 13.4.0, ansible.posix 2.2.2, community.sops 2.5.0), SOPS 3.13.3 + age, k3s v1.36.5+k3s1(stable 채널, 2026-10-18 확인), kubectl v1.36.5

**Spec:** `docs/superpowers/specs/2026-10-18-direction-change-design.md` (§5 1단계)

## Global Constraints

- 모든 플레이북·스크립트는 멱등, 실패 시 non-zero. 두 번째 `make host`는 `changed=0`
- 셸은 `set -euo pipefail` + shellcheck 통과. 커밋·Ansible 실행은 WSL에서, `make host`·`sudo`는 사용자가 실행
- 평문 시크릿·age 개인키 커밋 금지. 시크릿을 다루는 태스크는 `no_log: true`, 템플릿은 `diff: false`
- 버전은 모두 고정(`latest` 금지): k3s `v1.36.5+k3s1`, community.sops `2.5.0`, kubectl `v1.36.5`
- 방화벽 변경은 적용 전에 변경 내용을 사용자에게 보여주고 승인받기. 기존 SSH 세션을 유지한 채 새 세션으로 확인
- `kubectl delete` 등 파괴적 명령은 실행 전 사용자 확인 (복원 리허설의 테스트 ConfigMap 삭제 포함)
- CLAUDE.md·`docs/runbook.md`는 변경안 승인 후에만 수정
- 버킷 `june21621-homelab-k3s-backup`, 리전 `ap-northeast-2`, S3 접두사 `etcd/`
- Tailscale 주소 `100.124.153.34`, LAN `192.168.35.235`, 호스트명 `homelab`, Tailscale 이름 `kjt-home-server`

  - `k3s_tls_san: ["100.124.153.34", "kjt-home-server", "homelab"]`
  - `k3s_etcd_s3_bucket: june21621-homelab-k3s-backup`, `k3s_etcd_s3_region: ap-northeast-2`, `k3s_etcd_s3_folder: etcd`
  - `k3s_snapshot_cron: "0 */6 * * *"`, `k3s_snapshot_retention: 20`(로컬), `k3s_etcd_s3_retention: 28`(7일치)

`config.yaml.j2` 키: `token`, `cluster-init: true`, `secrets-encryption: true`, `write-kubeconfig-mode: "0600"`, `tls-san`, `disable: [servicelb]`, `etcd-snapshot-schedule-cron`, `etcd-snapshot-retention`, `etcd-s3: true`, `etcd-s3-bucket/region/folder/access-key/secret-key/retention`. 파일 0600 root, 태스크 `no_log: true` + `diff: false`.

`k3s.service.j2`: k3s 설치 스크립트가 만드는 유닛과 같게 — `Type=notify`, `ExecStartPre=-/sbin/modprobe br_netfilter`·`overlay`, `ExecStart=/usr/local/bin/k3s server`, `KillMode=process`, `Delegate=yes`, `LimitNOFILE=1048576`, `LimitNPROC=infinity`, `LimitCORE=infinity`, `TasksMax=infinity`, `TimeoutStartSec=0`, `Restart=always`, `RestartSec=5s`, `After=network-online.target`.

`traefik-config.yaml.j2`: `/var/lib/rancher/k3s/server/manifests/traefik-config.yaml`에 `HelmChartConfig`(name `traefik`, ns `kube-system`)로 `service.type: ClusterIP`. (ArgoCD 이전 단계라 허용. 5단계 이후 이 파일만 예외로 Ansible이 관리)

방화벽 규칙(적용 전 사용자 승인): `6443/tcp` in on `tailscale0`(comment `k3s-api-tailscale`), `from 10.42.0.0/16`(comment `k3s-pods`), `from 10.43.0.0/16`(comment `k3s-services`). LAN에는 아무것도 추가하지 않음.
